# LifePilot · 个人生活助手 项目计划书

> 版本：v1.0（2026-11-01）
> 一句话定位：**天气 + 待办 + 喝水打卡 + 习惯养成 + 自动周报**，一个聚合式的"个人生活驾驶舱"。
> 技术基调：NestJS 后端（用户指定）+ Next.js 前端（本文档选型并给出论证）。

---

## 1. 项目概述

### 1.1 背景与问题

效率工具市场高度碎片化：待办在 Todoist、习惯在打卡 App、喝水在另一个 App、周报靠回忆手写。用户每天要在 4~5 个 App 之间切换，数据无法互相利用——而恰恰是这些数据组合起来才有价值（例如：本周完成了多少待办、喝了多少水、坚持了几个习惯，拼起来就是一份现成的周报）。

市面上已有验证：**TickTick（滴答清单）正是靠"待办 + 日历 + 番茄钟 + 习惯"四合一策略，以性价比在 2026 年各评测中被列为最佳价值选择**。本项目采用同样的聚合思路，但聚焦"个人生活"而非"工作任务"。

### 1.2 目标用户

- 首要用户：**开发者/白领个人自用**（先服务好自己，再考虑泛化）
- 特征：希望一个入口解决"今天天气如何、今天做什么、有没有喝水、这周干了啥"

### 1.3 项目目标

| 目标 | 衡量标准 |
| --- | --- |
| 一个入口完成每日闭环（看天气→列待办→打卡→收提醒） | 核心流程 ≤ 3 次点击 |
| 周报零成本 | 周报由系统数据自动聚合生成，一键导出 |
| 提醒不扰人 | 免打扰时段 + 频控，用户可随时关闭 |
| 可持续演进 | 模块化架构，新功能 = 新增 NestJS Module |

## 2. 市场调研与竞品分析

### 2.1 竞品速览

| 产品 | 类别 | 值得借鉴的点 | 不借鉴的点 |
| --- | --- | --- | --- |
| **Todoist** | 待办 | 自然语言录入（"明天下午3点开会 p1"自动解析日期/优先级）是其最强卖点；协作项目 | 订阅制、纯工作导向 |
| **TickTick / 滴答清单** | 待办+习惯 | "待办+日历+番茄钟+习惯"四合一的聚合策略（本项目同思路）；内嵌番茄钟 | 功能入口较深 |
| **Things 3** | 待办 | 克制的设计、"今日聚焦（Today）"视图的仪式感 | 仅 Apple 平台 |
| **Habitica** | 习惯游戏化 | 完整 RPG 化（XP/等级/ avatar） | 两极分化，重游戏会劝退一部分人 |
| **Streaks** | 习惯 | 连击（streak）前置展示，激励感强 | 断一天清零，挫败感强 |
| **Loop Habit Tracker** | 习惯 | 开源；**宽容型连击**（按每周目标次数计，不因漏一天清零） | 仅 Android |
| **Finch** | 习惯 | 温和自我关怀路线（照顾一只小鸟） | — |
| **WaterMinder** | 喝水 | 按体重/活动量**个性化每日目标**；多种饮品水分系数；一键记录；大量小组件 | — |
| **Plant Nanny** | 喝水 | 喝水浇灌虚拟植物的游戏化隐喻 | — |
| **彩云天气** | 天气 | 分钟级降雨提醒（"40 分钟后下雨"），对国内用户极实用 | — |
| **ClickUp Brain / ONES / Asana AI** | AI 周报 | **从系统内已有的工作记录自动生成周报**，用户只做润色 | 依赖重项目管理体系 |
| **Forest** | 专注 | 番茄钟+种树的游戏化绑定 | — |

### 2.2 关键洞察（调研结论）

1. **录入摩擦决定生死**：Todoist 评测中反复被强调的是"最快的捕获（frictionless capture）"。→ 本项目待办必须支持自然语言一条输入。
2. **提醒是品类基线，但"提醒+价值"才是最佳实践**：学术内容分析显示 98% 喝水 App 有提醒，但 UX 研究指出提醒应附带饮水小知识/鼓励语，否则就是打扰。→ 通知中心统一设计"免打扰时段 + 频控 + 有内容的提醒"。
3. **连击（streak）设计要选边**：硬清零（Streaks）激励强但挫败强；宽容型（Loop，按周目标）留存更好。→ 本项目采用**宽容型连击**：按"每周 N 次"计连击周数，漏一天不清零。
4. **喝水目标必须个性化**：按体重 + 活动量计算基线（如 35ml/kg 起步），而不是一刀切 2000ml。
5. **周报的正确姿势是"数据自动聚合 + AI 可选润色"**：ClickUp Brain/ONES 的做法是周报由系统内记录生成，人只负责确认。→ 本项目周五定时从待办/喝水/习惯数据聚合出结构化周报，Markdown/图片导出；接 LLM 润色作为可选开关。
6. **天气是最佳"首页钩子"**：天气是每天必看的低频刚需，作为仪表盘首屏卡片能带动打开率；恶劣天气推送（降温/降雨）是天然的通知场景。

### 2.3 差异化定位

> **不做一个更全的待办工具，而做一个"把你的数据变成反馈"的生活驾驶舱。**
> 待办/喝水/习惯是数据采集端，仪表盘和周报是反馈端——这是单品类 App 做不到的。

## 3. 功能规划（P0/P1/P2 分期）

### 3.1 P0 — MVP（没有这些不发布）

| 模块 | 功能 |
| --- | --- |
| 账户 | 邮箱注册/登录（Argon2 + JWT），个人时区设置 |
| 天气 | 首页天气卡：当前天气 + 今日/未来 5 日预报 + 逐小时滑动条；城市管理（多城市）；天气数据缓存 10 分钟 |
| 待办 | 快速录入（标题 + 日期 + 优先级）；今日/即将到来/已完成视图；勾选完成；删除/编辑 |
| 喝水 | 一键 +250ml 记录（可改杯量）；每日目标环（个性化计算）；今日饮水时间线 |
| 习惯 | 创建习惯（名称/图标/颜色/每周目标次数）；每日打卡；宽容型连击展示 |
| 仪表盘 | 首页：天气卡 + 今日待办 + 喝水进度环 + 今日习惯一行卡 |
| 周报 | 每周五 17:00 自动聚合本周数据（待办完成率、饮水平均值、习惯连击、专注时长）生成结构化周报；Markdown 一键复制/导出 |
| 通知 | 站内通知中心；Web Push 喝水提醒（用户自定时间 + 免打扰时段） |

### 3.2 P1 — 上线后第一个月

- **自然语言录入**：接入 `chrono-node`（支持中文）解析"明天下午3点和老板开会 #工作 !p1"
- **提醒调度中心**：待办到期提醒、习惯打卡提醒、喝水定时提醒统一走 BullMQ 延迟/重复任务
- **通知渠道扩展**：邮件（Nodemailer）、飞书/钉钉/企业微信群机器人 webhook
- **统计页**：近 30 天饮水量柱状图、待办完成率趋势、习惯日历热力图
- **番茄钟**：25/5 计时，完成的番茄计入当日"专注时长"并进周报
- **PWA 完善**：可安装到手机主屏、离线骨架、图标

### 3.3 P2 — 远期探索

- **AI 周报润色**：接 OpenAI 兼容 API，把结构化周报转成"人话版"叙述（默认关闭，用户自填 key）
- **游戏化**：借鉴 Plant Nanny（喝水浇虚拟植物）/ Habitica（习惯得 XP）二选一做轻量版
- **国内分钟级降雨提醒**：接入和风天气（QWeather），"40 分钟后有雨记得带伞"推送
- **多设备同步增强 / 移动原生**：Expo React Native 复用接口层
- **健康平台集成**：Apple Health / Health Connect 导入步数等
- **i18n 中英双语**

### 4.2 后端选型与最佳实践（NestJS）

| 项 | 选择 | 理由 / 实践依据 |
| --- | --- | --- |
| 框架 | NestJS 11 + TypeScript strict | 用户指定；模块化单体，新功能=新 Module |
| ORM | **Prisma** | 类型安全 + 迁移管理成熟，比 TypeORM 更适合从零起步 |
| 数据库 | PostgreSQL 16 | 时区/JSONB/窗口函数（算连击、周聚合都靠它） |
| 缓存/队列 | Redis 7 + **BullMQ** | 定时提醒（repeatable job）、天气缓存、周报调度 |
| 认证 | Passport JWT：短效 access token + httpOnly Cookie 旋转 refresh token，Argon2 哈希 | SPA 安全基线 |
| 校验 | 全局 `ValidationPipe`（whitelist+transform）+ class-validator DTO | NestJS 官方推荐姿势 |
| API 文档 | @nestjs/swagger，URI 版本化 `/api/v1`，开发期 `/docs` 可视化 | 前后端协作契约 |
| 日志 | nestjs-pino（请求 ID 贯穿）+ pino-pretty（开发） | 结构化日志 |
| 安全 | helmet、CORS 白名单、@nestjs/throttler 限流 | 上线前 checklist 项 |
| 错误 | 全局异常过滤器统一返回 RFC 7807 `problem+json` | 前端可统一处理 |
| 健康检查 | @nestjs/terminus（/health，含 pg/redis 探针） | 部署探活 |

**天气模块采用 Provider 适配器模式**（本项目关键设计）：

```typescript
interface WeatherProvider {
  getCurrent(loc: Coordinates): Promise<CurrentWeather>;
  getDailyForecast(loc: Coordinates, days: number): Promise<DailyForecast[]>;
  getHourlyForecast(loc: Coordinates): Promise<HourlyForecast[]>;
}
// MVP 实现：OpenMeteoProvider（免费、无 key、全球覆盖，开发零成本）
// P2 实现：QWeatherProvider（国内分钟级降水、灾害预警）
```

**定时任务设计（BullMQ）**：
- 喝水提醒：按用户配置的提醒时间点注册 repeatable job（Redis 持久化，重启不丢）
- 周报：每周五 17:00（按用户时区）扫描用户表，逐个投递 `report:generate` 任务（幂等，带 dead-letter queue）
- 天气缓存：按城市 10 分钟 TTL 缓存，避免打爆第三方限额

### 4.3 前端选型论证（已按用户要求改为「移动原生优先」）

> **2026-11-02 修订**：用户明确需要手机原生 App 而非网页。最终采用 **Expo（React Native）为移动主力端**，Next.js PWA 保留为桌面仪表盘，NestJS 后端与共享包三端复用。

**结论：移动端 Expo SDK 58（RN 0.88）+ expo-router + NativeWind 5（Tailwind v4）+ TanStack Query；Web 端 Next.js 15 作为桌面补充。**

| 候选 | 是否选 | 理由 |
| --- | --- | --- |
| **Expo / React Native** | ✅ | 与 NestJS 同为 TS 生态、共享包直接复用；一套代码出 iOS/Android；expo-notifications 提供真正的系统推送与本地提醒；EAS 可出正式安装包 |
| Next.js 15 + PWA | ✅ 保留 | 已实现完成，作为桌面仪表盘继续使用；Web Push 与原生推送双通道并存 |
| Flutter | ✗ | 需引入 Dart 第二语言，共享类型/生态断裂 |
| 原生 Swift/Kotlin 双端 | ✗ | 个人项目成本翻倍 |

配套：**TanStack Query v5**（三端同构的服务端状态）、**zustand**（客户端状态）、**expo-secure-store**（令牌存 Keychain/Keystore）、**expo-notifications**（本地喝水提醒 + 远程周报推送）、**NativeWind 5**（Tailwind 语法跨端样式）。

## 6. API 设计概要（REST /api/v1，详见 Swagger）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /auth/register · /auth/login · /auth/refresh | 认证（refresh 走 httpOnly Cookie） |
| GET/PATCH | /users/me · /users/me/settings | 个人设置（含饮水目标、提醒时段） |
| GET/POST | /todos?view=today\|upcoming\|done | 待办列表/创建 |
| PATCH/DELETE | /todos/:id | 编辑 / 完成走 `PATCH {completed:true}` |
| POST | /todos/parse | （P1）自然语言解析预览，返回结构化字段 |
| GET/POST | /habits · POST /habits/:id/check-ins | 习惯与打卡 |
| GET | /habits/:id/streaks | 宽容型连击数据 |
| POST | /water/logs · GET /water/logs?date= | 记一笔水 / 当日时间线 |
| GET | /water/summary | 今日总量 + 目标进度环数据 |
| GET | /weather/current · /weather/forecast?cityId= | 天气（走缓存） |
| GET/POST/DELETE | /cities | 城市管理 |
| GET | /reports/weekly/latest · GET /reports/weekly/:id | 周报读取 |
| POST | /reports/weekly/generate | 手动触发重新生成 |
| POST | /push/subscriptions | Web Push 订阅登记 |

## 8. 质量保障与 DevOps

- **测试策略**：领域 Service 单测（Jest，目标覆盖 80%+，重点：连击算法、周报聚合、时区边界）；API e2e（Supertest + 独立测试库）；前端 Playwright 走"注册→建待办→喝水→看周报"主路径
- **代码质量**：ESLint + Prettier + husky + commitlint（Conventional Commits），CI 不绿不合并
- **CI/CD**：GitHub Actions → lint/test/build → 构建 Docker 镜像 → SSH 部署到 VPS `docker compose up -d`
- **部署拓扑**：Caddy（自动 HTTPS）反代 api/web；PostgreSQL 每日 `pg_dump` 异地备份；Redis 开 AOF
- **可观测**：pino 结构化日志 + /health 探针 + UptimeRobot 外部拨测

## 9. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| Web Push 在 iOS 上要求"先安装 PWA" | 高 | 首次访问做引导弹窗；邮件/飞书 webhook 作为兜底渠道 |
| 天气 API 限额/停服 | 中 | Provider 适配层隔离；10 分钟缓存；Open-Meteo 与和风可热切换 |
| 提醒过多导致用户关通知 | 中 | 免打扰时段默认开启；同类提醒每日频控；提醒附内容（饮水小知识） |
| 时区/夏令时计算错误 | 中 | DB 统一存 UTC；打卡存"用户本地日期"字符串；连击/周报按用户时区聚合；单测覆盖跨时区用例 |
| LLM 周报成本与合规 | 低 | 规则聚合版是基线功能，AI 润色为可选开关、用户自填 key |
| 范围蔓延（个人项目最大杀手） | 高 | 严格按 P0→P1→P2 分期；P0 清单外的一律进 backlog |
